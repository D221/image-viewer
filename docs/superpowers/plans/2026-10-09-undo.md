# Undo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `Ctrl+Z` and `Ctrl+Shift+Z` undo and redo turn, mirror, reset-turn, crop and clear-crop, per image, without touching the filesystem.

**Architecture:** A new `EditHistory` in `lib.rs` holding two `HashMap<PathBuf, Vec<Edit>>` stacks (past and redo) with one interface call, `record(path)`, made *before* an edit is applied. `main.rs` calls it from `apply_to_current`, which is already the shared tail for all four transform buttons, so the wiring is one line rather than four. Crop is the exception and records once on pointer-press rather than per drag frame.

**Tech Stack:** Rust 2021, `std::collections::HashMap`, existing `image_viewer::{Edit, ImageEdits, Crop, Xform}`. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-09-undo-and-ratings-design.md` — read §1 (Undo) before starting. The spec travels with this plan; executors read both.

## Global Constraints

- **Undo covers view transforms only.** Not zoom, pan, settings, ratings, or file operations. These are the contents of `ImageEdits`.
- **Undo must never write to the filesystem.** Ratings are explicitly *out of scope* here (spec §2), and that is what keeps `Ctrl+Z` a chord that cannot lose data.
- **`Edit` is `Copy`** (`#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]`, `src/lib.rs` ~4347), so history entries are pushed by value with no clone.
- **Every new bare letter must be added to `BARE_LETTERS`** in `tests/keybindings.rs` with the reason. `Ctrl+Z`/`Ctrl+Shift+Z` are chords and need no entry.
- **Full suite before every commit:** `cargo test --no-fail-fast` — 27 targets, currently all green.
- **Mutation-check every new source scan.** A scan that has not been verified to fail with its bug reintroduced is decoration.

## Review Focus

Five input/failure classes the spec implies but no step below exercises. Each has a test in the task that owns the code.

1. **Undo pressed when nothing was ever edited.** Expected: no change, no error, no notice — and specifically it must NOT silently undo a *different* image's edit by reading a shared stack.
2. **Undo across an image boundary.** Turn image A, navigate to B, undo. Expected: nothing happens (B has no history). Undo must be per-path, never global.
3. **A crop drag that never ends.** Press, drag 300 px, release outside the image. Expected: **one** history entry, not 300 — otherwise undo becomes useless after a single gesture.
4. **Redo after a new edit.** Turn, undo, mirror, then redo. Expected: redo does nothing, because the new mirror rewrote the future.
5. **Undo past the start of the stack.** 50 undos on one image with 3 recorded edits. Expected: the image sits at its original edit, unchanged, and further undos are no-ops — never a panic and never a *different* image's edit.

/// Truth table first; the naming here matches the fields so a reader can check

#[test]
fn undo_and_redo_walk_the_edit_history() {
    use image_viewer::{Edit, EditHistory, Xform};

    let p = std::path::Path::new("a.jpg");
    let mut h = EditHistory::default();

    // Review Focus #1: undo with nothing recorded is a no-op, not a panic.
    assert_eq!(h.undo(p, Edit::default()), None, "nothing to undo");
    assert!(!h.can_undo(p));
    assert!(!h.can_redo(p));

    // Record three states: identity, then turned, then turned twice.
    let a = Edit { xform: Xform::Identity, crop: None };
    let b = Edit { xform: Xform::Rot90, crop: None };
    let c = Edit { xform: Xform::Rot180, crop: None };
    h.record(p, a);
    h.record(p, b);
    h.record(p, c);
    assert_eq!(h.len_for(p), 3);
    assert!(h.can_undo(p));

    // Undo returns the *previous* state and moves the current one to redo.
    assert_eq!(h.undo(p, c), Some(b), "undo hands back the earlier edit");
    assert_eq!(h.undo(p, b), Some(a), "and again, to the original");
    assert_eq!(h.undo(p, a), None, "past the start is a no-op");
    assert!(h.can_redo(p));

    // Redo walks back the other way.
    assert_eq!(h.redo(p, a), Some(b));
    assert_eq!(h.redo(p, b), Some(c));
    assert_eq!(h.redo(p, c), None, "and stops");
}

- [ ] **Step 3: Implement `EditHistory` in `src/lib.rs`**

Add after the `ImageEdits` impl block. `cap` is 50 per path.

```rust
/// Two stacks per path: what has been done, and what can be redone.
///
/// **Per path, not one global list**, and that is the whole of the design
/// decision. Undo means "undo on *this* picture": someone who turns three photos
/// and then walks back to the first expects undo there to undo that photo's turn,
/// not to walk them through all three in reverse. A single global stack answers a
/// question nobody asked and gets the common case wrong.
///
/// `record` takes the *current* edit and must be called **before** the change, so
/// `undo` can hand back the state the image was in before it. That ordering is
/// the interface's contract and the reason a caller cannot get it wrong by
/// forgetting a "previous value" argument: there isn't one to pass.
///
/// Recording also clears redo for that path, because a new edit has rewritten
/// the future. That is what makes redo's absence after a new edit correct rather
/// than a bug.
```

Fields: `past: HashMap<PathBuf, Vec<Edit>>`, `redo: HashMap<PathBuf, Vec<Edit>>`, `cap: usize` (50 in `Default`).

- `record(&mut self, path, current)`: push `current` onto `past[path]`; if `past[path].len() > cap`, `remove(0)` (drop the **oldest**, so the newest edit is never the one refused); clear `redo[path]`.
- `can_undo` / `can_redo`: `self.past.get(path).is_some_and(|v| !v.is_empty())` and the same for `redo`.
- `undo(&mut self, path, current) -> Option<Edit>`: if `past[path]` is empty return `None`. Else pop it, push `current` onto `redo[path]`, return the popped value.
- `redo(&mut self, path, current) -> Option<Edit>`: mirror — pop `redo[path]`, push `current` onto `past[path]`, return it.
- `len_for(&self, path) -> usize`: `self.past.get(path).map_or(0, Vec::len)`.

```rust
/// The cap drops the **oldest** step, so the newest edit is never the one
/// refused: a viewer that silently ignored a rotate because its history was full
/// would be worse than one that forgot the deepest step.
#[test]
fn the_history_is_capped_and_drops_the_oldest_step() {
    use image_viewer::{Edit, EditHistory, Xform};
    let p = std::path::Path::new("a.jpg");
    let mut h = EditHistory::default();
    // 60 recorded states; the cap is 50.
    for i in 0..60u8 {
        h.record(p, Edit { xform: Xform::quarters_cw(i % 4), crop: None });
    }
    assert_eq!(h.len_for(p), 50, "the stack is bounded");
    // Undoing 50 times lands on the oldest surviving entry, and one more is a
    // no-op rather than a panic or another image's edit.
    for _ in 0..50 { let _ = h.undo(p, Edit::default()); }
    assert_eq!(h.undo(p, Edit::default()), None, "and it stops there");
}
```

Run: `cargo test --test unit the_history_is_capped` → PASS.

    ///
    /// **Reads `cur`, not `shown`**, and applies the result to `cur`'s path:
    /// the edit store is keyed by the file being edited, so restoring into a

    fn undo(&mut self, ctx: &Context) {
        let Some(p) = self.cur.clone() else { return };
        let restored = self
            .history
            .undo(&p.path, self.edits.get(&p.path));

            self.edits.set(&p.path, e);
            self.after_edit_change(ctx);
        }
    }
